# Baseball showcase operations

The showcase is disabled unless `SHOWCASE_ENABLED=true`. Node.js 22 or newer is required by DiceBear 10.x. Runtime avatars are generated by the official DiceBear library with the CC0 Notionists style; there are no calls to the public avatar service.

## First installation

1. Create a dedicated PostgreSQL test database and set `TEST_DATABASE_URL` to that database (distinct from `DATABASE_URL`) for the commands below. Never use a production URL for local validation or `prisma migrate dev`.
2. Apply the generated migrations to the test database with `DATABASE_URL="$TEST_DATABASE_URL" npx prisma migrate deploy` and regenerate with `npx prisma generate`.
3. Ensure a default, valid baseball `ScoringRule` exists. On an empty disposable database the application's baseline seed can establish one. The legacy `db:seed` is destructive to its seeded tournament fixtures; do not run it against an existing showcase or production database.
4. Run `npm run showcase:seed-users -- --profiles 30000 --dry-run`. Profiles come from RandomUser 1.4 with a fixed seed. The validated import manifest is cached in git-ignored `.showcase-data/`; protect and retain this directory to reproduce exactly the same import.
5. Inspect the counts, then run `npm run showcase:seed-users -- --profiles 30000 --apply`. Existing eligible demo account IDs and all their team/league relationships are preserved. Accounts with payments, owned leagues, or privileged roles are excluded. Existing demo sessions and authentication accounts are retired, and no passwords or paid credit grants are created.
6. Run `npm run showcase:seed-history -- --days 30 --participants 1500 --dry-run`, then the same command with `--apply`. This fetches and verifies the actual July 2025 MLB statistics before publishing each replay contest. Network failures stop the import, and a rerun resumes completed days without duplicates. No fake game results are substituted.
7. Set `SHOWCASE_ENABLED=true`, run `npm run showcase:tick`, and verify the new UI and API routes.

Commands default to `TEST_DATABASE_URL` and dry-run; writes require `--apply`. Access to the application database additionally requires `--production`. The default dataset seed is `baseball-showcase-v1`; pass `--seed` consistently to both profile and history imports when using another cohort. Reduced counts can be used for a quick isolated-database smoke test.

## Updates

The daily `/api/internal/cron/showcase` endpoint requires `Authorization: Bearer <CRON_SECRET>`, using the existing project cron convention. Authenticated viewers can refresh through the same-origin `POST /api/me/showcase/refresh`. Both use a shared lease/cooldown, and callers cannot supply a simulated clock, user ID or job key.

The runner publishes live contests three days ahead, clones verified replay days into upcoming replay contests, adds due demo entries in resumable batches, and refreshes results after the lock. The default processing budget is 20 seconds between work units; upstream calls and shared provider deadlines abort upstream calls; database transactions are bounded by remaining time. Repeating `npm run showcase:tick` after the cooldown safely continues outstanding work. Network and database delays are visible rather than replaced with fictitious results.

The profile/import scripts do not create transactions in the credit or payment ledgers. The overview distinguishes demo activity from real users. Replay and live rankings are independent.

## Production rollout and rollback

First verify the full cohort and history on the test database. Back up the working database and preserve the import manifest; inspect a dry-run against the working database using `--production --dry-run` before applying with `--production --apply`. Use `prisma migrate deploy` for production migration, then import and enable the feature.

To roll back visibility and stop jobs, set `SHOWCASE_ENABLED=false`. Keep the additive tables and history so the feature can be re-enabled. No reset, bulk delete or backwards destructive migration is needed. Existing weekly tournaments and payment records are unaffected by disabling the showcase.
