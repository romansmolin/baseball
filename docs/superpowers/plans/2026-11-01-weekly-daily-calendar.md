# Weekly Daily Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Публиковать Daily Classic на текущую и шесть следующих календарных дат вместо трёх дат.

**Architecture:** Единственный default горизонта находится в существующем сервисе публикации. Тот же сервис вызывают runner, cron и разовая административная проверка. Модель конкурса, правила Daily Classic и структура расписания сохраняются.

**Tech Stack:** Существующие TypeScript, Prisma/PostgreSQL, MLB provider, Next.js и Vitest. Новые зависимости не нужны.

**Spec:** `docs/superpowers/specs/2026-11-01-weekly-daily-calendar-design.md`

**Status:** Реализовано после согласования; пользователь дополнительно разрешил исключать отдельные матчи без актуальных ростеров.

## Global Constraints

- 7 календарных дат, включая сегодня, в `America/New_York`; UTC для времени матча и блокировки.
- Один Daily Classic на лигу/дату с `slateKey = classic`.
- Те же MLB, Triple-A, Double-A, Winter Leagues; только подтверждённые реальные матчи и допустимый пул игроков. По уточнению пользователя матчи без актуальных ростеров исключаются; остальные проверяются вместе.
- Существующие ID, участия, составы, сроки и история сохраняются при повторе.
- Без миграции схемы, новых игровых форматов, новых API-провайдеров или изменения расписания cron.
- Существующие бюджет tick 20 секунд и 15-минутный интервал календаря сохраняются.
- Продуктовые тексты — английские; FSD и серверные слои проекта сохраняются.

## Review Focus

1. Последний день входит в неделю, следующий — нет; позднее время UTC не сдвигает дату New York — задача 1.
2. DST и переход года сохраняют семь правильных дат и зимнюю привязку сезона — задача 1.
3. Повторный/конкурентный вызов сохраняет ключи, ID, записи участников и зафиксированные данные — задача 2.
4. Пустой источник или недостаточный оставшийся пул оставляют дату без конкурса; ошибки ростеров отдельных матчей не мешают остальным — задача 2.
5. Таймаут фоновой обработки не считается успешным заполнением; пройденные даты остаются доступными, выдача более 20 записей пагинируется — задачи 2–3.

## Self-review

План ограничен выбранным расширением календаря и согласованным исключением матчей без актуальных составов. Новые наборы матчей и мини-форматы исключены. Порядок фаз и интервал автоматического повтора сохранены.

## Результаты реализации и проверки

- RED→GREEN: недельный горизонт, границы дат и исключение матчей без ростеров. Пустой ответ MLB о ростере больше не прерывает календарь всей лиги.
- Временная PostgreSQL: проверены повторный и конкурентный запуски, сохранность существующих ID/составов, сроки блокировки и пагинация. С реальным источником тестовая база заполнилась на 1–7 ноября; повторное выполнение не создало дублей.
- Полный набор: 212 тестов прошли с отдельной PostgreSQL; TypeScript и targeted ESLint прошли; Webpack-сборка прошла.
- Холодный тестовый tick добавил 10 демоучастий и достиг лимита 20 секунд (`timedOut: true`, `calendarError`); это остаётся ограничением. Штатный обработчик приложения позднее создал четыре даты в диапазоне 4–7 ноября; каталог через repository возвращает семь дат, из них шесть открыты.
- Резервная копия рабочей БД создана и проверена через `pg_restore --list`; повторная публикация сохранила существующие ID и участия.
- Визуальная проверка в браузере не выполнялась. Коммиты не созданы: затронутые файлы содержат связанные незакоммиченные изменения предыдущих задач.
