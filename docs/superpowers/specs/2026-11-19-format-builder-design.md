# Конструктор по форматам + Generate with AI — дизайн (этап 1: H2H Points)

## Зачем
Пользователь готовит состав для внешней Fantasy-платформы (Yahoo, ESPN и др.). Он выбирает формат соревнования, задаёт правила своей лиги, набирает игроков вручную и нажимает **Generate with AI**, чтобы достроить состав. Состав можно сохранить черновиком и открыть позже.

## Цели этапа 1
- Выбор формата при создании команды (4 формата видны, работает только H2H Points).
- Настройки черновика: формат, период прогноза, частота замен, правила очков, слоты. Хранятся с командой.
- Реальный прогноз ожидаемых очков за период на данных MLB (без `proj` и `salary` от id).
- Generate with AI: пустой или частичный состав. Ручные игроки остаются в своих слотах.
- Предложение AI показывается с объяснением, принять или править дальше.
- Конкретная причина, если состав собрать нельзя. Черновик не теряется.
- Сохранение и повторное открытие (в том числе неполного состава). Старые команды открываются.

## Не цели этапа 1
- H2H Categories, Roto, DFS (импорт CSV конкурса с пулом slate, позициями и зарплатами) — следующие этапы.
- Парк-факторы, платуны, лайнапы дня, Statcast-поправки в прогнозе.
- Импорт правил лиги с Yahoo/ESPN. Правила вводятся вручную, есть пресет по умолчанию.
- Кэп зарплат: настоящих зарплат нет, в Points кэп выключен.

## Антицели
- Фейковые числа, выданные за прогноз. Нет данных — показываем «нет прогноза».
- AI-состав, который нарушает позиции, дублирует игроков или затирает ручной выбор.

## Подходы (выбран 1)
1. **Серверный сервис прогнозов** (выбран). Один расчёт для пула игроков и для AI, цифры совпадают. Минус: нужны статы на каждую команду, решается кэшем.
2. Расчёт на клиенте: дублирует логику в autofill. Отклонён.
3. Таблица прогнозов в БД по cron: лишняя инфраструктура для этапа 1. Отклонён.

## Дизайн

### Данные (Prisma, миграция через `migrate dev`)
`FantasyTeam` получает:
- `format` enum `FantasyFormat { H2H_POINTS H2H_CATEGORIES ROTO DFS }`, default `H2H_POINTS`.
- `forecastPeriod` enum `{ DAY WEEK SEASON }`, default `WEEK`.
- `lineupChanges` enum `{ DAILY WEEKLY }`, default `DAILY`. Отдельно от периода: лига может считать неделю и разрешать ежедневные замены.
- `scoringRules` Json: очки за события (см. ниже).
- `slotConfig` Json: список `{ slot, count }`, `slot ∈ P C 1B 2B 3B SS OF UTIL BENCH`. По умолчанию текущие 9 слотов.
- `salaryCap` Int? (null = нет кэпа).
Существующие команды получают значения по умолчанию. Старое поле `scoringPreset` не пишется и не читается UI, удаляется отдельной задачей.

`RosterSlot`: добавить `slotIndex` Int default 0 (несколько слотов одного типа). `salaryAtLock` → nullable. Сохранение разрешено для 0..N игроков (черновик). Состав «полный», если заполнены все слоты из `slotConfig` (считается, не хранится).

### Правила очков (`scoringRules`)
Hitting: `single double triple homeRun run rbi walk hitByPitch stolenBase strikeOut`. Pitching: `inningPitched strikeOut earnedRun hitAllowed walkAllowed win save`. Все числа, могут быть отрицательными. Пресет по умолчанию — наш общий (не копия правил Yahoo/ESPN), редактируется в настройках.

### Сервис прогнозов — `server/services/projections/`
`projectPoints({ player stat lines, rules, period, scheduleGames })` возвращает `{ points | null, games, starts, reason? }`, `reason ∈ NO_STATS | INACTIVE | NO_GAMES`.
- Питчер-старт: число стартов за период из вероятных питчеров (`getGameContexts`), где данных нет — по ротации (команда играет N игр, СП стартует ≈ N/5). Реливер: появления по доле от игр команды.
- Hitter: ставка события на игру сезона × ожидаемые игры за период (игры команды × доля игр игрока, статус «недоступен» → 0).
- Малая выборка (порог из `estimates.const`) → `confidence: low`, показывается пользователю.
- Межсезонье (нет игр в периоде): считаем по темпу сезона (6 игр в неделю, 1 в день) и помечаем «оценка межсезонья». Иначе в ноябре конструктор пуст.
Статы берутся через `getPlayersByTeam({ statsSeason })`; последний сезон со статами, если текущий пуст. Кэш на время запроса и короткий TTL.

### API
- `POST /api/me/projections` `{ league, teamIds, period, rules }` → `{ [playerId]: Projection }`. Route парсит body, схема Zod в `server/entities/`, контроллер → сервис.
- Схемы `createTeam` / `updateLineup` расширяются полями выше, `players.min(1)` → `min(0)`, `max` из `slotConfig`.
- `GET /api/me/teams` отдаёт настройки; клиентский маппер восстанавливает их.
- Autofill-вход: `format`, `period`, `rules`, `slotConfig`, `filledSlots` (со `slotIndex`), `salaryCap?`.

### Generate with AI
- Пул считает тот же сервис прогнозов. Оптимизатор (детерминированный, максимум суммарных ожидаемых очков при совпадении по позициям, без дублей, только доступные, кэп если задан) выбирает состав для пустых слотов. Ручные игроки неприкосновенны.
- Модель получает итоговый состав и пишет короткое объяснение ключевых выборов. Её собственные пики больше не определяют состав (в старой схеме cheap-модель плохо решала задачу размещения).
- Результат: `{ picks, unfilled: [{ slot, code, message }], explanation }`. Коды: `NO_ELIGIBLE_PLAYER`, `NO_PROJECTION`, `CAP_TOO_LOW` (например «Осталось $2,400, самый дешёвый доступный SS стоит $2,700»), `POOL_EMPTY`. Частичный результат применяется, причины показываются, черновик не затирается.
- UI: предложение показывается как превью с «Принять» и «Отклонить». Принятие записывает в состав, отклонение возвращает прежний черновик.

### UI
- Шаг формата при создании: 4 карточки с объяснением результата. H2H раскрывает Points / Categories. Недоступные форматы помечены «скоро».
- Панель настроек: период, частота замен, слоты (счётчики по позициям), правила очков (сетка + «сбросить»).
- Пул игроков: колонка ожидаемых очков за период, «нет прогноза», пометки low confidence / межсезонье.
- Слоты: список слотов; ромб из 9 позиций остаётся для пресета по умолчанию.
- Ручной выбор в слот уже «закрепляет» игрока (AI его не трогает). Отдельный флаг lock не вводим.
- Логика в хуках, UI чистый, фетчеры в `withErrorHandling`, DTO только в `api/` (правила `CLAUDE.md`).

### Тесты
По одному целевому тесту на изменение: математика прогноза (правила → очки, питчер-старты, межсезонье), оптимизатор (закреплённые сохранены, нет дублей, позиции, кэп, невозможный случай с точной причиной), маппер настроек. Миграция проверяется открытием существующей команды.

## Критерии приёмки этапа 1
- Два игрока добавлены вручную, Generate with AI, сохранение, повторное открытие: оба на своих местах, остальные слоты заполнены.
- Смена правил очков меняет ожидаемые очки и ранжирование пула.
- Невозможный состав: показана конкретная причина, черновик остаётся доступным.
- Старые команды открываются после миграции.

## Решения за исполнителя / на проверку
- Состав выбирает оптимизатор, AI только объясняет (мой выбор, проверь).
- Пресет правил по умолчанию наш, не платформенный (мой выбор).
- `scoringPreset` оставлен в БД без использования.
- Открытый вопрос для плана: как сейчас хранятся LF/CF/RF в `RosterSlot` при enum без них (проверить маппер на сервере).
